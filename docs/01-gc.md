# КТ №40. GC в .NET 10: поколения, регионы памяти (DATAS)

Вариант 2 — «Измерение давления».

## Цель

Измерить, как сценарии с разным характером аллокаций нагружают поколения
управляемой кучи, и объяснить полученные значения счётчиков.

## Что реализовано

| Файл | Назначение |
|---|---|
| `Gc/GcSnapshot.cs` | снимок `CollectionCount(0..2)`, `GetTotalAllocatedBytes(precise: true)`, `HeapSizeBytes` и вычисление прироста |
| `Gc/GcObserver.cs` | вывод `GC.GetGCMemoryInfo()`: размер кучи, committed, нагрузка памяти, доля пауз |
| `Gc/PressureScenarios.cs` | три сценария варианта 2 + контрольная сборка Gen2 |

Сценарии (каждый — отдельный метод, счётчики снимаются до и после):

1. **Мелкие объекты** — `byte[100]` × 100 000, ссылки не сохраняются.
2. **Крупные объекты** — `byte[100_000]` × 10 (больше порога LOH 85 000 байт).
3. **Удерживаемые объекты** — `byte[512]` × 20 000 в `static List<byte[]>`.
4. **Принудительный Gen2** — `GC.Collect(2, Forced, blocking: true)` для проверки.

В начале работы фиксируется `GC.GetTotalAllocatedBytes()`, в конце выводится
общий объём аллокаций.

## Команда запуска

```bash
dotnet run --project src/MemoryLifecycle -c Release -- gc-pressure
```

## Выводы

1. **Gen0 нагружают мелкие короткоживущие объекты.** Каждый `byte[100]` рождается
   в Gen0 и сразу становится мусором; при исчерпании бюджета запускается дешёвая
   эфемерная сборка, выживших почти нет, поэтому Gen2 не растёт.
2. **Крупные объекты не трогают Gen0.** Массивы ≥ 85 000 байт сразу попадают в LOH,
   который логически относится к Gen2. Аллокации заметны (~0,95 МБ на 10 объектов),
   но счётчик Gen2 растёт только при *сборке*, а ~1 МБ обычно не исчерпывает бюджет LOH —
   поэтому немедленной сборки нет.
3. **Gen2 нагружают долгоживущие данные.** Объекты из статического списка переживают
   сборки и продвигаются Gen0 → Gen1 → Gen2. Их вклад в `HeapSizeBytes` виден только
   после очередной сборки — это показывает сценарий 4, после которого размер кучи вырастает.
4. `HeapSizeBytes` до экспериментов может быть равен 0: `GetGCMemoryInfo()` описывает
   последнюю *завершённую* сборку, а её ещё не было.
5. Принудительная сборка Gen2 увеличивает все три счётчика: полная сборка учитывается
   и как сборка младших поколений.
